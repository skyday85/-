# Единое настольное приложение — архитектура 1.0

## Цель

Пользователь работает в одном настольном приложении, а не переключается между отдельными системами. Приложение является единым интерфейсом для Главного агента, почты, финансов, автопарка, продаж, маркетинга, закупок и последующих модулей.

## Основные разделы одного окна

1. Главный агент — центральный чат и рабочая панель поручений.
2. Почта — единая лента всех подключённых почтовых аккаунтов.
3. Финансы и планирование — финансовые операции, ДДС, план/факт, счета, задолженности.
4. Управление автопарком — техника, ТО, ремонты, топливо, документы, запчасти, закупки.
5. Продажи — лиды, клиенты, сделки, заказы, задачи.
6. Маркетинг — кампании, источники, касания, лидогенерация, эффективность.
7. Задачи и уведомления — общая очередь действий от Главного агента и специализированных агентов.

## Почтовый контур

Несколько почтовых аккаунтов разных провайдеров подключаются через отдельные адаптеры и отображаются в единой ленте. Пользователь всегда видит исходный ящик, отправителя, получателей, цепочку, вложения и результат классификации Сборщика писем.

Сборщик писем не владеет почтой и не хранит пароли. Он работает через OAuth/API-коннекторы и передаёт структурированные события Главному агенту.

## Настольная оболочка

Целевая версия должна запускаться как desktop-приложение. Рекомендуемая архитектура: web-интерфейс как основа UI + desktop shell. Desktop shell не должен содержать бизнес-логику или прямой доступ к БД; он отвечает за окно приложения, безопасное локальное хранение пользовательской сессии, системные уведомления, открытие файлов и интеграцию с ОС.

На первом этапе допускается единая web-кодовая база с desktop-обёрткой. Архитектура должна сохранять возможность параллельной работы web-версии без дублирования бизнес-логики.

## Безопасность

- Основные пароли почтовых ящиков не сохраняются.
- OAuth access/refresh tokens хранятся только в защищённом секретном хранилище серверной части или системном secure storage, если это требуется desktop-клиенту.
- Desktop-приложение не получает прямых реквизитов баз данных.
- Все действия Главного агента и специализированных агентов журналируются.
- Security Control («Красная кнопка») остаётся независимым внешним контуром и не встраивается в desktop UI как доступная Главному агенту разрушительная функция.

## Принцип единого окна

Desktop UI — это единая точка входа. Источники данных остаются отдельными приложениями и сервисами, а Главный агент координирует их через API и специализированных агентов.
