# Почтовый сервис — первая рабочая версия

Эта ветка добавляет раздел **Управление почтой → Загрузить письма** к единому
приложению (React/Tauri, Mac и iPhone). Она пока не является размещённым
сервисом и не принимает пароли внешней почты.

## Реализовано

- Администратор создаёт пользователей и назначает им определённые источники писем.
- Можно загрузить файлы .eml и .mbox из нескольких почтовых ящиков.
- Для каждого импорта явно выбирается адрес исходного ящика.
- Сервис сохраняет тексты, заголовки и допустимые вложения в локальном контуре,
  создаёт категории и показывает одну карточку для идентичных писем из разных
  источников. Оригинальные экземпляры и адреса получения сохраняются.
- Повторная загрузка уже известных писем не создаёт новых экземпляров.
- Архивные источники только для чтения. Импорт НЕ удаляет письма, НЕ отправляет
  их и НЕ включает автоматическую пересылку.
- Источники разграничены по организации и назначенным пользователям.

## Ограничения первой версии

- Это именно **импорт файлов**. Онлайн-авторизация Mail.ru, Yandex и Timeweb
  по IMAP и безопасное хранение их паролей приложений пока не реализованы.
  Не отправляйте пароли в чат и не вводите их в прототип.
- В одной загрузке допускается один .eml либо .mbox до 45 МБ и не более
  1000 сообщений. Большие архивы следует разбить; превышение лимита
  приводит к явной ошибке без молчаливого пропуска.
- Вложения больше 12 МБ в текущем импорте пропускаются. Исходный .eml остаётся
  неизменным в загруженном пользователем файле.
- Локальная SQLite база — среда разработки; перед хранением реальной
  корпоративной переписки требуется развёртывание с защищённым хранилищем
  и полноценной проверкой подлинности сотрудников.
- Корректность нескольких владельцев одного ящика и поставщик-специфические
  особенности необходимо отдельно проверить на реальных примерах.

## Пример первого рабочего процесса

1. В почтовом клиенте на Mac подключить каждый рабочий ящик по IMAP
   с его паролем приложения; не передавать пароль в проект.
2. Экспортировать письма за выбранный период в .mbox либо сохранить
   выбранные письма в .eml. По возможности отделить старые архивы.
3. В приложении открыть **Управление почтой → Загрузить письма**.
4. Ввести адрес, например основной рабочий адрес, выбрать файл и загрузить.
5. Повторить для остальных ящиков. В разделе **Почта** посмотреть общую ленту
   и отображаемые адреса получения для дубликатов.
6. Назначить пользователям архивные источники через **Назначение почтовых ящиков**.

## Следующий технический этап

Сделать онлайн-IMAP коннекторы Mail.ru, Яндекса и Timeweb в выделенном
credential-owning Mail Gateway; TLS + проверка сертификата, ограниченный
набор IMAP-хостов, шифрование ключей вне основного приложения. Добавить
компонент загрузки писем за 30 дней и фоновую синхронизацию. SMTP —
отдельная возможность только после настройки и подтверждения правил.
Перед выпуском подключить реальную аутентификацию пользователей, провести
сквозные испытания с тестовыми ящиками и развернуть серверный компонент.

## Для разработчика

В каталоге ai/main-agent:

    python3 -m venv .venv
    source .venv/bin/activate
    pip install -r requirements-http.txt -r mail_gateway/requirements.txt

Обязательные локальные настройки: APP_ENV=development,
APP_ORGANIZATION_ID=<локальная организация>,
MAIL_BOOTSTRAP_OWNER_USER_ID=local-development-user,
MAIL_BOOTSTRAP_OWNER_EMAIL=<ваша почта>,
MAIL_DATABASE_PATH=<отдельный локальный путь>.

Запуск HTTP API только на loopback:

    uvicorn http_api.app:app --host 127.0.0.1 --port 8000

Клиент в каталоге clients/unified-app:

    npm install
    VITE_MAIL_ONLY_MODE=true VITE_API_BASE_URL=http://127.0.0.1:8000 npm run dev -- --host 127.0.0.1 --port 1420

Этот локальный режим — только разработка/тесты. Не открывайте его в сеть
и не загружайте конфиденциальную реальную почту до выпуска с полноценной
аутентификацией и защищённым хранилищем.
