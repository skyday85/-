# ADR-001: Собственный репозиторий Главного агента и доступ к проектам

Статус: архитектурное решение; миграция и выдача доступа пока не выполнены.

## Границы репозиториев

- `skyday85/main-agent` (целевой отдельный репозиторий): оркестрация, планирование, память/контекст, аналитика, реестр агентов, интеграционные контракты и коннекторы. Главный агент не копирует предметную логику приложений.
- `skyday85/mail-service` (целевой отдельный репозиторий): учетные записи почты, OAuth, токены, синхронизация, сообщения и вложения, пользовательский почтовый интерфейс. Агент-сборщик получает события и разрешенный доступ через сервисный API.
- `skyday85/fleet-management`: данные и бизнес-логика автопарка, закупок и документов.
- `skyday85/finance-planning`: финансовая бизнес-логика, включая подтверждение пользователем классификации.
- Новые приложения имеют самостоятельные репозитории и API/события для подключения к Главному агенту.

Существующая реализация Главного агента и прототип почты находятся в `skyday85/-`. Переносить по отдельным этапам с сохранением истории, сборок и API-совместимости; не сливать экспериментальные ветки в `main` без проверки.

## Право доступа к исходному коду других проектов

Главный агент использует отдельную GitHub App, установленную владельцем на все согласованные репозитории (текущие и добавляемые в будущем). Доступ ко всем репозиториям означает возможность их обнаружения и чтения; запись ограничивается разрешенными задачами и явно заданными репозиториями.

Начальные разрешения: metadata:read, contents:read, pull_requests:read, issues:read, checks/actions:read (при необходимости). Для одобренного режима разработки дополнительно contents:write **только в рабочих ветках**, pull_requests:write, issues:write. Запрещены права по умолчанию на управление репозиториями, секретами, учетными данными и обход защиты веток.

Каждый запрос к GitHub привязан к конкретному пользовательскому/системному полномочию; действия логируются (кто, когда, репозиторий, ветка, задача, SHA, PR). Токены краткоживущие и выдаются backend-брокером по необходимости. Не хранить токены в промптах, коде или репозитории.

## Правила изменений

1. Реестр проектов содержит repo, назначение, API-контракт, разрешения, владельца и статус подключения; неизвестные репозитории нельзя изменять.
2. Главный агент анализирует все разрешенные репозитории, строит зависимости и предлагает межпроектные изменения.
3. Правки только в feature-ветках; все изменения проходят тесты и Pull Request; защита `main`, обязательные проверки и подтверждение ответственного.
4. Автоматические обновления и деплой только согласно утвержденным политике, окружению и полномочиям.
5. Удаление репозиториев, переписывание истории, массовые удаления и экстренное управление/удаление данных не доступны Главному агенту. Независимый контур «Красная кнопка» находится за пределами этих прав.
6. Разрешения GitHub не дают прямого доступа к производственным базам, OAuth-токенам почты или финансовым операциям: используются отдельные авторизованные API.

## Этапы реализации

1. Создать приватный `skyday85/main-agent`; перенести оркестратор, контракты и тесты из `skyday85/-`.
2. Выделить `skyday85/mail-service`; оставить в Главном агенте только коннектор и агента-сборщика.
3. Зарегистрировать репозитории и права в реестре проектов; настроить GitHub App, необходимые разрешения и защиту веток.
4. Провести тест: чтение всех разрешенных репозиториев -> изменение в отдельной ветке тестового проекта -> CI -> PR -> пользовательское подтверждение; убедиться, что чтение секретов и запись в `main` недоступны.
